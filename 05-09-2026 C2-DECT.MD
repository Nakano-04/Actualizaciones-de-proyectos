## 1. Resumen Ejecutivo

Integrar el motor de orquestación por voz **Xile** (basado en Python asyncio, VAD, TTS y streaming) con el framework **C2-DECT** (servidor Go, agentes Go/Rust, GUI C#) para permitir que un operador de Red Team controle todo el ciclo de ataque mediante **comandos de voz**, sin necesidad de teclear en la consola o la GUI.

El resultado es un **"Voice C2"** que acelera la toma de decisiones y reduce la carga cognitiva durante ejercicios de Red Team, permitiendo ejecutar desde `sysinfo` hasta despliegues completos de worm con una simple frase.

**KPIs Críticos:**

| ID | Objetivo | Métrica DoD |
| :--- | :--- | :--- |
| VCO-01 | Autenticación automática contra C2-DECT | Xile obtiene JWT al arrancar y lo renueva si expira |
| VCO-02 | Traducción de voz a comandos C2 | 90% de los comandos hablados (30+ frases típicas) se mapean a herramientas o APIs |
| VCO-03 | Ejecución de comandos en agentes | `sysinfo`, `screenshot`, `desktop`, `shell` se ejecutan en el agente indicado por voz |
| VCO-04 | Despliegue lateral (Worm) | Órdenes como "lanza el worm contra la subred 10.0.0.0/24" disparan el motor Rust |
| VCO-05 | Feedback TTS inmediato | El operador escucha el resultado de la acción en <2s tras finalizar la orden |

**Componentes nuevos/modificados:**

- `jarvis/connectors/c2_client.py`: Cliente asíncrono para la API REST del C2.
- `jarvis/core/c2_tools.yaml`: Definición de herramientas C2 (mapeo voz → endpoint).
- `jarvis/audio/cues/`: Nuevos sonidos para eventos C2 (`agent_checkin.wav`, `exploit_success.wav`).
- `config/c2_credentials.env`: Almacena `C2_HOST`, `C2_USER`, `C2_PASS`.
- `docs/C2_VOICE_COMMANDS.md`: Lista de comandos de voz soportados.

**Decisiones de Diseño:**

1. **Concurrencia:** Xile mantiene `concurrencia=1` (una orden a la vez) para evitar conflictos. Las tareas largas del C2 (compilación de agente) se ejecutan con timeout de 15s y se marcan como `background`; el resultado se notifica posteriormente.
2. **Contexto de Sesión C2:** Xile mantiene un `c2_session_id` por `InteractionContext`. El operador puede decir "interactúa con el agente 5" y todos los comandos posteriores se dirigen a ese ID.
3. **Autenticación:** Al iniciar, Xile hace login con credenciales fijas (admin/c2-dect) y almacena el JWT. Si recibe 401, renueva automáticamente y reenvía la orden.
4. **Telemetría:** Xile genera un `trace_id` que se incluye en el header `X-Trace-ID` en cada llamada al C2, permitiendo correlacionar logs de voz con logs del servidor.

## 3. Mapeo de Herramientas (Tools) de Voz a C2

| Frase de ejemplo (voz) | Tool Xile | Endpoint C2 / Acción |
| :--- | :--- | :--- |
| *"Lista los agentes"* | `c2.list_sessions` | `GET /api/sessions` |
| *"Información del sistema del agente 3"* | `c2.run_sysinfo` | `POST /api/sessions/:id/task` con `{"command":"sysinfo"}` |
| *"Captura pantalla del agente 2"* | `c2.screenshot` | `POST /api/sessions/:id/task` con `{"command":"screenshot"}` |
| *"Abre escritorio remoto en el agente 1"* | `c2.desktop` | `POST /api/sessions/:id/task` con `{"command":"desktop 9090"}` (abre navegador automáticamente) |
| *"Ejecuta shell 'whoami' en el agente 4"* | `c2.shell` | `POST /api/sessions/:id/task` con `{"command":"shell whoami"}` |
| *"Despliega el worm contra 192.168.1.0/24"* | `c2.deploy_worm` | 1) Subir `worm.exe` (via `upload`), 2) `POST /api/sessions/:id/task` con `{"command":"worm <base64_binary>|service"}` |
| *"Explota BlueKeep contra 10.0.0.5"* | `c2.exploit_bluekeep` | `POST /api/exploits/execute` con `{"exploit":"bluekeep", "target":"10.0.0.5"}` |
| *"Prepara un stager para Windows"* | `c2.delivery_stager` | Llama al CLI de Delivery Kit (`delivery_cli.py stager-build`) y reporta URL |
| *"Estado del último despliegue"* | `c2.delivery_status` | Lee `delivery/out/telemetry.jsonl` y resume funnel |
| *"Mata el agente 7"* | `c2.kill_agent` | `DELETE /api/sessions/:id` |

**Fast-Path:** Los comandos más comunes (`list agents`, `sysinfo`, `screenshot`) se detectan por regex y se ejecutan sin pasar por el LLM, garantizando latencia <200ms + TTS.

## 4. Plan de Implementación (Sprint de Integración – 5 días)

### Fase 0 – Preparación (0.5d)
- Crear rama `feature/voice-orchestrator` desde `develop`.
- Definir credenciales en `config/c2_credentials.env` (ejemplo).
- Configurar entorno virtual Python con dependencias de Xile + `aiohttp`.
- **DoD:** `pytest tests/test_c2_auth.py` pasa contra el servidor Go en local.

### Fase 1 – Cliente C2 y Herramientas Base (2d)
- **1.1** `jarvis/connectors/c2_client.py`: implementar `C2Client` con métodos `login()`, `list_sessions()`, `send_task(sid, cmd)`, `delete_session(sid)`, `execute_exploit(exploit_name, target)`.
- **1.2** `jarvis/core/c2_tools.yaml`: definir esquema de herramientas con `timeout`, `cancellable`, `atomic`.
- **1.3** Extender `fast_path.py` y `stream_parser.py` para reconocer las frases clave y convertirlas en tools.
- **1.4** Integrar en `orchestrator.py`: al detectar tool `c2.*`, llamar al `C2Client` en lugar de a `FileManager`.
- **DoD (Gate 1):** Decir *"Lista los agentes"* y Xile devuelve la lista por TTS. Prueba con sesiones reales (al menos una conectada).

### Fase 2 – Contexto y Control de Sesión (1.5d)
- **2.1** Añadir `c2_session_id` a `InteractionContext`. Comando *"interactúa con el agente <id>"* fija ese ID.
- **2.2** Implementar renovación automática de JWT al recibir 401.
- **2.3** Manejo de comandos largos: timeout de 15s para compilaciones/exploits; si expira, notificar *"La operación continúa en segundo plano"*.
- **DoD (Gate 2):** Interrumpir un `shell dir C:\` con voz corta la espera y no deja colgado el worker.

### Fase 3 – Integración con Delivery Kit y Worm (1d)
- **3.1** Crear `jarvis/connectors/delivery_client.py` que ejecuta `delivery_cli.py` con parámetros y parsea la salida.
- **3.2** Comando *"Prepara stager para el agente <id>"*: toma el payload del agente, llama a `delivery_cli.py stager-build` y devuelve la URL.
- **3.3** Comando *"Despliega worm en subred X"*: sube `worm.exe` (desde `modules/lateral-rust/target/release/`) al agente y ejecuta `worm <base64>|service`.
- **DoD (Final):** Desplegar un worm en un entorno de pruebas y recibir confirmación por TTS de los hosts infectados.

## 5. Riesgos y Mitigaciones

| # | Riesgo | Impacto | Mitigación |
| :--- | :--- | :--- | :--- |
| R-01 | Token JWT expirado durante ejecución larga | Fallo de la orden | Capturar 401, renovar token y reenviar la petición (idempotente si es posible) |
| R-02 | Comando de voz malinterpretado | Ejecución de acción incorrecta | Incluir confirmación previa (ej. *"¿Deseas ejecutar exploit en 10.0.0.5? Responde sí/no"*) antes de acciones destructivas |
| R-03 | Tiempo de compilación de agente (hasta 20s) | TTS timeout y corte | Marcar como `background`; Xile sigue escuchando pero no bloquea; notifica cuando el binario está listo vía cola de eventos |
| R-04 | El agente de destino no responde | Tarea colgada en C2 | Xile usa `asyncio.wait_for` con 10s para la llamada REST; si timeout, dice *"El agente no responde, verifica conexión"* |
| R-05 | Solapamiento de voz con TTS | El operador escucha su propio eco | Usar el sistema de VAD con `is_speaking` y suspender TTS mientras el operador habla (ya implementado en Xile) |

## 6. Checklist de QA para la Feature

- [ ] Xile arranca y se autentica contra el C2 (log `JWT obtained`).
- [ ] Al decir *"lista agentes"*, se obtiene la lista con IDs y direcciones IP (TTS).
- [ ] Al decir *"sysinfo del agente 1"*, se recibe la salida del comando y se lee (o se muestra en HUD).
- [ ] Al decir *"screenshot agente 2"*, se descarga la imagen y se muestra en la GUI (opcional).
- [ ] Al decir *"interactúa con agente 5"*, todos los comandos posteriores usan ese ID.
- [ ] Al decir *"lanza BlueKeep contra 10.0.0.5"*, se ejecuta el exploit y se recibe confirmación.
- [ ] Al decir *"prepara stager Windows"*, se genera un `stager.exe` y se devuelve la URL de descarga.
- [ ] Al decir *"despliega worm en 192.168.1.0/24"*, se inicia el worm y se reporta el número de hosts infectados.
- [ ] Interrupción durante un comando largo (ej. `shell findstr`) corta la espera en <1s y no deja procesos huérfanos en el C2.
- [ ] Los logs de Xile (`logs/run_*.jsonl`) incluyen `c2_session_id` y `trace_id` para correlación.

## 7. Próximos Pasos (Backlog para v0.2.0)

- **Integración con WebSocket del C2:** Usar SignalR/WS para recibir eventos en tiempo real (nuevos agentes, tareas completadas) y anunciarlos por voz.
- **Control de múltiples C2:** Soportar varios servidores C2 (balanceo o failover).
- **Mejora de seguridad:** Añadir autenticación por voz (biometría) o verificación de frase de paso antes de órdenes críticas.
- **Modo "Táctico":** Xile propone acciones basadas en el estado de la red (ej. *"Detectado agente en 10.0.0.5 con privilegios altos, ¿deseas moverte lateralmente?"*).

## 8. Recursos Necesarios

  - Xile (Python 3.10+) con dependencias.
  - Delivery Kit y Worm compilados (Rust).
- **Entorno:** Laboratorio con al menos 2 máquinas Windows para pruebas de movimiento lateral.
